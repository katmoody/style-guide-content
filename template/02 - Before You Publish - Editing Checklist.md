# 02 - Before you publish: editing checklist

Run through this list before you publish or update any doc. It takes a few minutes, and it catches most of what readers would trip over.

> **Template note:** Notes like this are instructions for whoever sets up the guide. **Delete them before you publish.** (How to customize: §00.)

> **Customize (A7):** Move the checks that match your team's top pain points to the top of the list.

## Content

- [ ] The title says what the doc helps you do (§04).
- [ ] The most important information comes first.
- [ ] You followed the steps yourself, and they work (§04).
- [ ] Facts, names, and numbers are correct, especially anything drafted with AI (§11).

## Language

- [ ] Spelling and grammar are checked. Run your tool's spell-check.
- [ ] Wordy and awkward phrasing is cut (§06).
- [ ] The doc talks to the reader as "you," in active voice and present tense (§06).
- [ ] Acronyms are spelled out on first use, and terms match the word list (§06).

## Structure and formatting

- [ ] Headings are in order, with no extra formatting inside them (§04).
- [ ] The doc isn't mostly lists. If a section needs explaining, it's a paragraph (§04).
- [ ] Buttons and menu names are **bold**. Code, file names, and variables use `code formatting` (§04).
- [ ] Callouts are used sparingly (§04).

## Links

- [ ] Every link works. Check links to shared files (like Google Drive) closely, since those get moved and deleted often.
- [ ] Every Slack channel, team, or tool named in the doc still exists and hasn't been renamed.
- [ ] Link text describes where it goes, and links point to the source of truth (§04).
- [ ] [Your tool's link style, for example: internal links use Confluence smart links.]

## Accessibility and safety

- [ ] Every meaningful image has alt text, and no important text appears only in an image (§07).
- [ ] Color isn't the only way to show meaning (§07).
- [ ] No passwords, customer data, or other sensitive information, including in screenshots (§10).

## Last step

- [ ] The doc lists an owner and a "Last reviewed" date (§12).
- [ ] If this is a new kind of doc or a new location, the Documentation Map is updated (§05).

**Make it yours:** Keep track of the mistakes you make most often, and add them to your own copy of this list. That's how this checklist started: as one editor's mental checklist that kept growing.
